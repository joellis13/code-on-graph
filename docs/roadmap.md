**Why this order.** A real plan is in your hands at the end of Phase 1, so retrieval and planning problems show up before anything is tuned. Phase 1 calls the model directly through `LLMClient` (OpenRouter: one key, many models) because Planning is built on `LLMClient`; agent CLIs are `AgentRunner`s and are not used for planning ([ADR-0004](decisions/0004-two-provider-interfaces.md)). The thin `Index` stays as the lexical-only fallback, so nothing is thrown away: later phases deepen the same nodes and add the others. Phase 3 tests the two bets the design rests on, deterministic context building and plans a small model can execute, before the remaining nodes are built on them.

Copilot's BYOK mode, or Claude Code, may be the fastest stopgap for early Implementation work, while `NativeRunner`, the intended runner and the point of the project, matures (see [Providers](explanation/providers.md)).

## 5. Risks

| Risk                                           | Impact                       | Mitigation                                                                                                                                                                 |
| ---------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vendor CLI or SDK behavior changes             | Runner breaks                | Pinned versions; live contract tests; runners are optional                                                                                                                 |
| Subscription terms change or prove restrictive | Cheap path disappears        | Direct providers are the base; runners can be disabled by config                                                                                                           |
| LangGraph API changes                          | Upgrade pain                 | Version pin; checkpoint round-trip test; thin wrapper conventions                                                                                                          |
| Index recall is the ceiling on plan quality    | Weak plans                   | Recall eval before tuning; per-retriever measurement                                                                                                                       |
| Windows-specific process and path issues       | Flaky Implementation         | `cog` runs in WSL2 on Windows; containers for Implementation; Linux CI plus a Windows smoke job                                                                            |
| WSL2 data loss or resource starvation          | Lost plans; slow machine     | Opt-in backup directory, `cog backup`, `wsl --export`, `.wslconfig` limits, `cog doctor` checks ([Platforms and environments](explanation/platforms-and-environments.md))  |
| Command discovery misses a repo's commands     | Plans lack acceptance checks | Config overrides; provenance and confidence on every entry; Phase 2 measurement on the owner's repos; gated `custom_argv` (ADR-0019)                                       |
| Undeclared file edits during Implementation    | Failed tasks or conflicts    | Detect-and-review scope rule (ADR-0020)                                                                                                                                    |
| GitHub rate limits                             | Slow or failed runs          | Local clones and mirror; GraphQL for fan-out; conditional requests; budget accounting                                                                                      |
| Prompt injection through issue text            | Unsafe actions               | Untrusted-text delimiting; read-only tools; deny-list; sandbox                                                                                                             |
| Scope growth before value                      | Never ships                  | Rounds end at sign-off ([ADR-0021](decisions/0021-sign-off-and-living-specification.md)); a real plan in Phase 1; detail added just in time; Implementation designed later |
| Deterministic preload loses to agentic search  | The central design bet fails | Phase 3 agentic-search baseline on the golden set; adopt what wins, measured                                                                                               |
| Plans are not executable by small models       | Planning optimizes a proxy   | Phase 3 execution trial before the plan schema hardens; `schema_version` for changes                                                                                       |
| Documentation drifts between pages             | Contradictory specification  | Consistency checklist in `AGENTS.md`; docs check in CI from Phase 1                                                                                                        |
